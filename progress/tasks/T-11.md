# T-11 - Host behaviour collector v1

- Owner: F | Status: Done | Window: Nov W2–W4 | Completed: 2026-11-15

- Acceptance tests:
  - [x] A helper that spawns a subprocess, writes a file and opens a socket yields all three events, attributed to the correct skill, including a double-forked grandchild (evidence: tests/skills/test_skills_collector.py)
  - [x] An idle benign skill yields zero events (evidence: tests/skills/test_skills_collector.py)
- Evidence: `python -m cim.skills observe --db <path> [--skill <id>]`; module `cim.skills.collector`; org PR #7
- Added 2026-11-24: `python -m cim.skills exec --db <path> [--root <dir>] <skill> -- <script> [args]` (module `cim.skills.execute`, tests `tests/skills/test_skills_exec.py`). An agent harness runs one helper through it: in its scope under the collector, recorded with `record_behaviour`, its stdout (byte for byte), stderr and exit code passed back. A script outside the skill (absolute, `..`, symlink) exits 126, an unknown skill 127, no systemd user session or strace 125 (the helper is not run). Output is still capped at 1 MB per stream, delivered after the helper ends. Store writes go through one function (`store_behaviour`, ADR-007). Checked by hand on 5 corpus skills, including `meeting-brief` on the A3 trigger notes (egress recorded, files unchanged), against `python -m cim.skills board`. It becomes `cim skills exec` in T-13.
- Deviations: observation is a syscall trace (`strace -f` inside the invocation's cgroup scope), not `/proc` polling with psutil as the plan describes. Polling saw one process where the trace sees five on the seed corpus, never sees a refused connection, and gives a different record from run to run; the envelope (T-15) needs the same record every time. Attribution is still the cgroup scope. One behaviour record is written per invocation, also for an idle helper: its lists are empty ("zero events"), which T-15 needs to count invocations. auditd is not used. Two rules were added after the first CI run so that Ubuntu and Fedora give the same record: a failed connect to a unix socket is not egress (Ubuntu programs try the name-service cache socket at start-up), and helpers run with `PYTHONDONTWRITEBYTECODE=1` (a first import on a fresh machine otherwise shows up as a file write).
- Notes: The live tracer tests run on the GitHub runner. Needs strace and permission to trace a child process (tests skip without it). The `domain` destination class is never produced: destinations are classed by address. Same-user limits are documented at the top of `collector.py` and `scoped.py` (a helper can tell it is traced, and can tamper with a trace file it owns); the boundary is decided in ADR-007: one user and a precisely worded claim for FYP I; the monitor and store as their own `cim` user for FYP II. Baselines written before the record hash formula is settled are throwaway (S2, proposed fix ADR-006). Not yet run on VM-MON (the lab is not built).
