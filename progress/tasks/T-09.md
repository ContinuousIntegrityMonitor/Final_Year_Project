- Deviations:
  - The v1.0 contract has no field for response size, JSON-RPC method, or the `initialize` exchange. Calls are stored as `McpBehaviourPayload` (host-side fields empty until T-14); size is captured in memory but not stored. Contract v1.1 request is in `docs/FASIH_REVIEW.md` (joint).
  - Malformed-frame alerts use an unvalidated `alert` payload because the contract defines no alert schema yet.
  - The real-client test failed once on Windows on a cold first run, then passed 21 runs in a row; CI (Linux) is the reference.
- Notes: Config via `CIM_PROXY_DB`, `CIM_PROXY_SERVER_ID`, `CIM_PROXY_ORIGIN`, `CIM_PROXY_ROOT`. A real `tools/list` from the pinned HexStrike checkout was captured on the dev PC (150 tools). Decimal defaults in those schemas are stringified before hashing. A tool call on VM-MON is still open. The attack API was not started.
- Review fixes (2026-11-15, branch `t09-proxy-fixes`, PR open for Hamza): capture can no longer stop forwarding (P1); a frame capture could not handle, or an event the store could not take, leaves a `proxy_capture_failed` alert (D1, proxy half); `cim proxy` returns 127 or 126 instead of hanging when the server cannot start (P2); later sessions reuse the server's and each tool's artefact row (P3). Not changed: the `invocation_id` format, which still repeats across sessions and is part of the contract v1.1 discussion.
