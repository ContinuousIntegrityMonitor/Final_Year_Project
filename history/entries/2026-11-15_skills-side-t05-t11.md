# 2026-11-15 — Skills side: T-05 finished, T-08, T-10 and T-11 built

- A review pass over the runner found ten faults, each reproduced first: a helper that exited within milliseconds could leave a daemon behind unseen, a process could hide in a sub-cgroup, and output that was not UTF-8 crashed the run. Fixed in org PR #2.
- The scoped runner now holds the helper behind a start gate until its cgroup is known. That made the leak check certain where it had been a race.
- Seed corpus: 11 benign skills and 3 inert suspicious ones, with a checksum manifest (`t05-seed-corpus`).
- T-08 inventory and T-10 watcher share one rule: the store's view of a skill is its baseline plus the integrity events after it, so a change is reported once. Notifications only trigger a sweep; every event comes from comparing hashes.
- T-11 uses a syscall trace instead of the `/proc` polling in the plan. Polling saw one process where the trace sees five on the corpus and cannot see a refused connection. Recorded as a deviation in `progress/tasks/T-11.md`.
- CI on Ubuntu disagreed with Fedora three times (a multi-call coreutils binary, a name-service socket probed by every program, bytecode written on first import). Each became a fix, which is the argument for running everything on VM-MON soon.
- Open: a helper running as the same user can leave its cgroup and can tamper with its own trace. The stronger boundary is undecided. None of this has run on VM-MON. The branches after PR #2 are stacked and have no PRs yet.
